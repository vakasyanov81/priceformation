# Project conventions (always apply)

## Подавление ошибок линтера и типов

Подавлять нарушения (`# noqa`, `# type: ignore`, `# pyright: ignore`, whitelist vulture) **можно только в крайнем случае**. Сначала найти способ исправить: переименовать, сузить тип, вынести функцию, убрать мёртвый код.

### Прод-код (`src/`)

Нельзя: `# noqa: WPS214` / `# type: ignore` без попытки поправить.

Можно на время **длительного рефакторинга по плану** (тикет ещё впереди). Тогда рядом обязателен комментарий `FIXME`: что не так, почему сейчас нельзя починить, **когда** починят (номер задачи / этап).

```python
# ❌ BAD — заглушить и забыть
class MarkupPolicy:  # noqa: WPS214
    ...


# ✅ GOOD на время плана
class MarkupPolicy:  # noqa: WPS214  FIXME: 02.2 — хук percent раздует класс; снять в 06 после выноса предикатов
    ...
```

Когда задача из `FIXME` делается — снять `noqa` и комментарий, а не копировать подавление дальше.

### Тесты (`tests/`, `integration_tests/`)

Подавлять тоже только в крайнем случае (например доступ к приватному API политики, который иначе не проверить). Не глушить «шум», который лечится короче именем теста, константой или хелпером.

## Проверки после изменений

После того как изменения в коде сделаны и показаны пользователю, **обязательно** выполнить проверки ниже. Не считать задачу завершённой, пока все команды не прошли успешно.

Всегда запускать по **всему репозиторию**. Не сужать scope до изменённых файлов, каталогов или затронутых тестов.

### Порядок

1. **Тесты** — из корня проекта:

```bash
uv run pytest
```

Если тесты упали — исправить и перезапустить.

2. **Black** (форматирование с флагами проекта):

```bash
uv run black --line-length 120 --target-version py311 --skip-string-normalization .
```

3. **Ruff с автофиксом**:

```bash
uv run ruff check --fix .
```

После `--fix` перечитать затронутые файлы при необходимости и убедиться, что ruff завершился с кодом 0. Если остались неисправляемые нарушения — поправить вручную и снова запустить `uv run ruff check --fix .`.

4. **Flake8 (WPS)** — стиль wemake, конфиг из `setup.cfg`:

```bash
uv run flake8 .
```

Правила запуска:
- Через `uv run` (не системный `flake8`)
- Не переопределять флаги (`--select` и т.п.), если пользователь не просил — берётся `setup.cfg`
- При нарушениях — исправить и перезапустить flake8 до exit 0

5. **Mypy** — строгая проверка типов, конфиг из `pyproject.toml` (`[tool.mypy]`):

```bash
uv run mypy .
```

Правила запуска:
- Через `uv run` (не системный `mypy`)
- Не переопределять флаги (`--strict` и т.п.), если пользователь не просил — берётся `[tool.mypy]`
- При ошибках — исправить и перезапустить mypy до exit 0

6. **Vulture** — поиск неиспользуемого кода, конфиг из `pyproject.toml` (`[tool.vulture]`):

```bash
uv run vulture
```

Правила запуска:
- Через `uv run` (не системный `vulture`)
- Не передавать пути и флаги, если пользователь не просил — берутся `paths` и `min_confidence` из `[tool.vulture]`
- При находках — убрать мёртвый код или явно пометить ложные срабатывания и снова запустить `uv run vulture` до exit 0

7. **Bandit** — статический анализ безопасности Python-кода, конфиг из `pyproject.toml` (`[tool.bandit]`):

```bash
uv run bandit -r src -c pyproject.toml
```

Правила запуска:
- Сканируется только директория `src` (тесты и прочее исключены в `[tool.bandit]`)
- При находках — исправить или явно пометить как ложное срабатывание (`# nosec`) и перезапустить до exit 0

8. **pip-audit** — аудит зависимостей на известные уязвимости:

```bash
uv run pip-audit
```

Правила запуска:
- Через `uv run` (не системный `pip-audit`)
- При находках — обновить версии библиотек в `[project] dependencies` и/или `[dependency-groups] dev`

### Когда применять

- После любой правки Python-кода, конфигов тестов/линта или связанной инфраструктуры
- Перед тем как объявить задачу выполненной

### Когда можно пропустить

- Чистый вопрос без правок файлов
- Пользователь явно попросил не запускать тесты/линт
