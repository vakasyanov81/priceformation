# Формирование прайс-листов

Программа собирает общий прайс-лист из прайс-листов поставщиков шин: названия
позиций, закупочные цены, остатки и другие параметры. Наценка считается
автоматически по заданным правилам. Поведение каждого поставщика описывается
одним JSON-файлом, поэтому новый поставщик добавляется без изменения программы.

## Как запустить

Нужен Python 3.14 и менеджер пакетов [uv](https://docs.astral.sh/uv/).
Установка зависимостей — `uv sync`.

Запуск выполняется из корня проекта (текущий каталог значения не имеет — пути
считаются от файлов проекта):

```
uv run pf              # интерактивное меню
uv run pf parse --json # разбор без меню, ответ в JSON
```

Точка входа называется `priceformation`, есть короткий алиас `pf` — это одно и
то же. Из justfile то же самое: `just run` (меню) и `just run parse --json`.
Готовые скрипты запуска без тестовых зависимостей — `src/run.sh` (Linux) и
`src/run.bat` (Windows).

## Папки и файлы

```
parse_config/                 настройки (не код)
    vendors/<folder>.json     конфиг поставщика, имя файла = имя папки прайсов
    mail.json                 доступ к почтовому ящику и профили поставщиков
    black_list                чёрный список позиций
    manufacturer_aliases.json синонимы брендов
    title_aliases.json        синонимы названий
    correct-nomenclature.xlsx справочник номенклатуры
    dummy/                    примеры настроек

file_prices/                  входные прайсы и результат
    <folder>/                 прайсы одного поставщика
    result/                   готовые прайс-листы
```

Папка поставщика в `file_prices` совпадает с именем его конфига:
`parse_config/vendors/poshk.json` ↔ `file_prices/poshk/`. Внутри лежат файлы,
подходящие под маски `file_templates` (для Excel — например `price*.xls*`,
для JSON-источников — свои имена, у Запаски `disk.json` / `tire.json`).

## Результат

Готовые файлы складываются в `file_prices/result`:

| Файл | Для чего |
|---|---|
| `price_<дата>.xlsx` | прайс для внутреннего использования (`for_inner`) |
| `price_drom_<дата>.xlsx` | прайс для drom.ru (`for_drom`) |
| `price_full_<дата>.xlsx` | полный прайс (`for_full`, только по явному запросу) |
| `doubles_<дата>.xlsx` | отчёт о дублях (команда `doubles`) |

## Команды

Без аргументов открывается интерактивное меню (пункт `h — справка` открывает
этот README в постраничном просмотрщике — `less` или `$PAGER` — с подсветкой
заголовков, кода и ссылок). Для сторонних скриптов доступны подкоманды:

- `parse` — разобрать прайсы поставщиков и записать файлы;
- `doubles` — разобрать прайсы и записать отчёт о дублях;
- `zapaska_load_api_data` — выгрузить прайсы Запаски по API;
- `fetch_mail_prices` — скачать свежие прайсы поставщиков из почты;
- `get_supliers` — вернуть каталог поставщиков:
  `{"1": {"sup_code": "poshk", "sup_title": "Пошк"}}`;
- `load_supplier_prices` — разложить файлы прайсов по папкам поставщиков:
  `{"1": "/путь/прайс.xls"}` или `{"poshk": "/путь/прайс.xls"}`. Ключ — ИД
  поставщика или `sup_code`. Файл перемещается в `file_prices/<sup_code>/price.xls`
  (или `.xlsx`); допускаются только `xls` и `xlsx`;
- `load_config` — положить файл или папку настроек в `parse_config`: путь к
  `*.json`, `*.xlsx`, `black_list` или к папке с такими файлами. Файлы
  перемещаются с теми же именами (существующие заменяются). Файл из папки
  `vendors/` кладётся в `parse_config/vendors/` — удобно заливать конфиги
  поставщиков.

### Флаги

- `--json` — одна JSON-строка в stdout, логи не печатаются; прайсы пишутся в
  `.jsonl`, рядом — `result_meta.json`;
- `--all-result` — включить в JSON сами позиции разбора (без флага — только
  статистика); сам по себе тоже включает JSON-режим;
- `--clear-previous-result` — очистить `file_prices/result` перед записью;
- `--result-template NAME` — для `parse`: записать только этот шаблон
  (`for_inner`, `for_drom`, `for_full`). Без флага — `for_inner` и `for_drom`
  (`for_full` только явно). Неизвестное имя — ошибка.

### Формат ответа

Код выхода: `0` при успехе, `1` при ошибке. Во всех JSON-ответах есть
`ok` и `elapsed_seconds` (секунды). У команд `parse` / `doubles` дополнительно:
`action`, `stats`, `files`, `warnings`, `suppliers`, `disabled_suppliers`,
`positions`, `error`. У остальных команд — только `ok`, `action`, `files`,
`error`.

В `.jsonl` каждая строка — объект с ключами `"1"`, `"2"`, … вместо названий
колонок; расшифровка — в `result_meta.json` в той же папке. Ключи со значением
`null` в строку не пишутся. Повторяющиеся значения заменяются короткими кодами
`"@1"`, `"@2"`, словарь — в `values`.

### Примеры

```
uv run pf parse --json --clear-previous-result
uv run pf parse --json --all-result
uv run pf parse --json --result-template for_drom
uv run pf doubles --json
uv run pf zapaska_load_api_data --json
uv run pf fetch_mail_prices --json
uv run pf get_supliers
uv run pf load_supplier_prices='{"poshk": "/full/path/price.xls"}'
uv run pf load_config=/full/path/vendors/mim.json
uv run pf load_config=/full/path/settings_dir
```

## Получение прайсов из почты

Команда `fetch_mail_prices` (и пункт меню) скачивает свежее письмо с прайсом для
каждого поставщика по IMAP и кладёт вложение в `file_prices/<папка>/price.xlsx`.

Настройки — в `parse_config/mail.json`:

```json
{
  "imap": { "host": "imap.timeweb.ru", "port": 993, "folder": "INBOX" },
  "profiles": {
    "pioner": {
      "enabled": 1,
      "sender": "rmv@pionersib.ru",
      "subject_keyword": "прайс",
      "attachment_glob": "*.xlsx"
    },
    "poshk": {
      "enabled": 1,
      "sender": "nortec-tyres.ru",
      "sender_is_domain": 1,
      "attachment_glob": "прайс*.xlsx"
    }
  }
}
```

- ключ профиля — папка поставщика в `file_prices`;
- `sender` — точный адрес; при `sender_is_domain: 1` — домен, на который
  оканчивается адрес отправителя;
- `subject_keyword` — подстрока темы (регистр не важен); не задана — тема не
  фильтруется;
- `attachment_glob` — маска имени вложения (регистр не важен). Письмо
  подходит, только если во вложении ровно один файл по маске;
- `enabled: 0` временно выключает профиль.

Логин и пароль ящика в файле не хранятся: они берутся из `MAIL_LOGIN` /
`MAIL_PASSWORD` (переменные сессии или `.env`, см. `.env.example`), а при
интерактивном запуске недостающее запрашивается у пользователя. В
неинтерактивном режиме (`--json`, cron) отсутствие данных — ошибка.

## Настройки

Все настройки лежат в `parse_config`. Каждый поставщик описывается одним
JSON-файлом; остальные файлы действуют на прайсы всех поставщиков.

- `enabled` в конфиге поставщика включает (`1`) и выключает (`0`) его разбор.
  Выключенные поставщики попадают в `disabled_suppliers`.

## Поставщик — один JSON-файл

Поведение поставщика полностью описывается файлом `parse_config/vendors/<folder>.json`.
Имя файла (без `.json`) совпадает с именем папки поставщика в `file_prices`.

Пример:

```json
{
  "enabled": 1,
  "code": "1",
  "name": "Пошк",
  "start_row": 14,
  "file_templates": ["price*.xls", "price*.xlsx"],
  "reader": "xls",
  "category": { "strategy": "title_keywords", "map": { "шина": "Легковая шина" }, "default": "Разное" },
  "title": { "strategy": "normalize_size_chunks", "fallback_brand": "Алтайшина" },
  "pricing": { "policy": "map_on_opt", "rules": { "markup_rules": { "rule_70": { "min": 0, "max": 201, "percent": 0.7 } } } },
  "behavior": { "min_rest": 0 },
  "sections": [
    {
      "sheet_indexes": [0],
      "columns": { "0": "code", "1": "title", "2": "price_opt", "3": "rest_count" }
    }
  ]
}
```

### Уровень поставщика

| Ключ | Обяз. | Значение |
|---|---|---|
| `enabled` | да | `1` — разбор включён, `0` — выключен |
| `code` | да | внешний ИД каталога (например `1`, `22`); по умолчанию `id` секций |
| `name` | да | название поставщика (по умолчанию для секций) |
| `start_row` | да | номер первой строки данных, счёт с 1 (по умолчанию для секций) |
| `file_templates` | да* | маски файлов прайсов в `file_prices/<folder>/` |
| `reader` | нет | `xls` (по умолчанию) или `json` |
| `columns` | нет | маппинг колонок по умолчанию для секций |
| `pricing` | нет | наценки по умолчанию для секций |
| `category`, `title` | нет | стратегии по умолчанию для секций |
| `behavior` | нет | общие переключатели разбора |
| `sections` | да | непустой список секций — по одной на лист/файл |

\* `file_templates` и `columns` обязательны хотя бы на одном уровне: у
поставщика либо у каждой секции.

### Уровень секции

Секция — один лист (для `xls`) или один файл (для `json`). Отсутствующие ключи
берутся у поставщика.

| Ключ | Значение |
|---|---|
| `id` | ИД каталога; по умолчанию `code` поставщика |
| `name` | название; по умолчанию `name` поставщика |
| `start_row` | первая строка данных; по умолчанию у поставщика |
| `file_templates` | маски файлов; по умолчанию у поставщика |
| `sheet_info` | метка листа, добавляется к названию в отчёте |
| `sheet_indexes` | индексы листов xls, счёт с 0; пусто — все листы |
| `columns` | маппинг колонок; **заменяет** маппинг поставщика целиком |
| `category`, `title`, `pricing` | переопределяют одноимённые слоты поставщика |

Один поставщик может иметь несколько секций с разными `id` (например Запаска →
`2` диски и `22` шины) или несколько секций с одним `id` (Мим — три вкладки).

### Колонки

`columns` — карта `{"<источник>": "<поле позиции>"}`:

- при `reader: "xls"` ключ — индекс колонки (с 0) строкой: `"1": "title"`;
- при `reader: "json"` ключ — имя ключа исходной JSON-записи: `"cae": "code_art"`.

Поле, не указанное в `columns`, остаётся пустым. Основные поля:

```
code  code_man  code_art  title  manufacturer_name  brand  model
season  spike  width  height_percent  diameter  ext_diameter  tire_type
index_load  index_velocity  construction_type  axis  layering  intimacy
camera_type  inscription_on_the_side  run_flat  us_aff_designation
disk_thickness  slot_count  pcd1  pcd2  eet  central_diameter  fastener
disk_type  disk_type_1  color  main_color
price_opt  price_recommended  rest_count  reserve_count  delivery_period
condition  available  type_production
```

### Поведение разбора (`behavior`)

| Ключ | По умолчанию | Значение |
|---|---|---|
| `min_rest` | `4` | минимальный остаток; `0` — отсечка выключена |
| `rest` | `count` | `count` — остаток как есть; `minus_reserve` — `rest_count - reserve_count` |
| `skip_markup_without_opt` | `false` | не наценять строки без закупа |
| `zero_rest_without_category` | `false` | без категории остаток обнуляется |
| `collect_missing_recommended` | `false` | собирать строки без РРЦ в отчёт |
| `find_manufacturer_on_enrich` | `true` | искать производителя при обогащении |
| `pipeline` | `["title","min_rest","category","markup"]` | порядок шагов разбора строки |

`pipeline` принимает только шаги `title`, `min_rest`, `category`, `markup`.

## Стратегии разбора

Стратегия задаётся именем в слоте; неизвестное имя — ошибка конфига с путём до
ключа.

### `category` — тип товара строки

| Стратегия | Параметры | Что делает |
|---|---|---|
| `none` | — | не менять категорию из прайса (по умолчанию) |
| `fixed` | `value` | одна категория для всех строк секции |
| `title_keywords` | `map`, `default` | по вхождению ключевого слова в название (порядок ключей в `map` важен) |
| `field_map` | `field`, `map`, `default` | по значению поля через карту (регистр и пробелы нормализуются) |
| `column_canonical` | `unknown_skip` | канонизировать категорию из колонки; неизвестные → пусто |
| `header_rows` | `zero_rest_categories`, `map`, `default` | категория из строк-заголовков (первый кусок канонизируется встроенной картой: `автошина` → `Автошина` и т.п., `map` из конфига дополняет её); у перечисленных категорий остаток обнуляется |
| `tire_size_category` | — | тип по размеру и маркерам в названии: `Грузовая шина`, `Легкогрузовая шина`, `Легковая шина`, `Спецшина`, а также `Автокамера`, `Диск`, `Ободная лента` |

Дополнительно в слоте `category`:

- `size_fields` — карта «тип, определённый по размеру названия → поля позиции».
  Тип считается независимо от стратегии слота: так Пошк, STK и Пионер получают
  сезон у грузовых и спецшин. Незаполненные поля получают значения из конфига,
  уже проставленные не перетираются;
- `calculate_type` — включить независимое определение типа: заявленный
  стратегией тип сохраняется для сверки, а в `type_production` пишется
  вычисленный (см. «Определение типа товара»). По умолчанию выключено.

### `title` — подготовка названия

| Стратегия | Параметры | Что делает |
|---|---|---|
| `default` | — | оставить название как есть (по умолчанию) |
| `normalize_title` | — | схлопнуть пробелы, десятичную запятую привести к точке |
| `normalize_size_chunks` | `fallback_brand` | нормализация названий Пошка: срезать обёртки «Шина»/«а/п», `*`→`x`, «н.с.N»→`PRN` |
| `stk_tire_compose` | — | собрать название STK/Пошка: размер, бренд, модель, нагрузка/скорость, PR, камера, назначение |
| `tire_compose` | `variant` | собрать название шины: `mim_simple`, `mim_truck`, `four_tochki` |
| `disk_compose` | `variant` | собрать название диска: `four_tochki` |
| `fill_fields_from_title` | — | разобрать размер и модель из названия, само название не менять (Автоснабжение) |
| `manufacturer_from_category` | — | производитель из раздела-категории (Пионер) |

Флаги слота:

- `aliases: true` — дополнительно заменить название по `title_aliases.json`;
- `markers` — карта «подстрока названия → поля позиции»: если название содержит
  маркер, незаполненные поля получают заданные значения (регистр не важен).
  Например, у Пошка «шип» означает зиму и шипованую шину.

## Ценообразование

Наценка поставщика задаётся слотом `pricing`; у секции может быть свой
`pricing`, который переопределяет поставщика.

Политики (`policy`):

- `base` — наценка по карте `rules` (по умолчанию);
- `identity` — без наценки (цена в прайсе уже отпускная, например Автоснабжение);
- `map_on_opt` — наценка по карте `%` от закупа;
- `recommended_or_map` — РРЦ, если она есть, иначе карта `%`;
- `recommended_range` — как `recommended_or_map`, но с диапазоном процента по
  категории (`category_markup_ranges`) и абсолютным полом (Форточки);
- `percent_by_threshold` — фиксированный процент в зависимости от закупа:
  `rules.threshold`, `rules.low`, `rules.high` (наценка Мим, грузовая вкладка).

Правило содержит диапазон закупочных цен (`min`/`max`) и процент наценки
(`percent`):

```json
"pricing": {
  "policy": "base",
  "rules": {
    "markup_rules": {
      "rule_70": { "min": 0, "max": 201, "percent": 0.7 },
      "rule_50": { "min": 200, "max": 301, "percent": 0.5 },
      "rule_40": { "min": 300, "max": 501, "percent": 0.4 }
    },
    "min_recommended_percent_markup": 0.14,
    "max_recommended_percent_markup": 0.27,
    "absolute_markup_rules": { "min_absolute_markup": 200, "markup_percent": 1.5 }
  }
}
```

Примечания:

- ключ правила (`rule_70` и т.п.) — произвольное уникальное имя, в алгоритме не
  участвует;
- если для закупочной цены нет подходящего диапазона, наценка идёт по
  минимальному проценту из `markup_rules`.

Необязательные настройки:

- `min_recommended_percent_markup` / `max_recommended_percent_markup` —
  минимальная и максимальная допустимая наценка по РРЦ;
- `replace_small_recommended` — подменять ли РРЦ картой `%`, когда наценка по
  РРЦ меньше минимума (`false` по умолчанию — если РРЦ есть, её не трогают);
- `absolute_markup_rules.mode` — что делать, если рублёвая маржа меньше
  `min_absolute_markup`: `multiplier` (по умолчанию) — цена = `закуп * markup_percent`;
  `delta` — цена = `закуп + min_absolute_markup`;
- `category_markup_ranges` — допустимый диапазон процента по категории товара
  (политика `recommended_range`), ключ — имя типа (`Грузовая шина`, `Диск`, …),
  значение — `{min, max}`.

### Примеры поставщиков

- **Пошк** — `map_on_opt`, `min_rest: 0`, категория `tire_size_category`,
  название `stk_tire_compose` с маркером «шип»;
- **Мим** — три секции; легковые и диски — `base`, грузовая вкладка —
  `percent_by_threshold`;
- **Форточки** — `recommended_range`: диапазоны по категориям и абсолютный пол
  `mode: delta`, `+500 ₽`; названия `tire_compose(four_tochki)` и
  `disk_compose(four_tochki)`;
- **Запаска** — `reader: json`, `base` с порогом РРЦ 8 %,
  `replace_small_recommended: true`, абсолютный пол `mode: delta`, `+150 ₽`;
- **Автоснабжение** — `identity`: цена в прайсе уже отпускная;
- **STK** — все настройки (включая наценку) в своём файле.

## Чёрный список

Файл `parse_config/black_list`. Действует на всех поставщиков. Каждая строка —
одно правило, пустые строки пропускаются.

- **Точное название** — строка без `*` исключает позицию, если наименование
  совпадает целиком;
- **Маска** — при наличии `*` это шаблон без учёта регистра, `*` означает любую
  последовательность символов. Например `*некондиция*` — фраза где угодно в
  названии, `восстановленная*` — название начинается с этой фразы.

## Алиасы производителей (брендов)

Файл `parse_config/manufacturer_aliases.json`. Действует на всех поставщиков.
Поставщики пишут один бренд по-разному («Michelin» / «Мишелин», «BF Goodrich» /
«BFGoodrich», «Белшина» / «БШК»), а файл задаёт каноническое имя и варианты.

Ключ — как бренд должен выглядеть в результате, значение — массив написаний,
встречающихся у поставщиков:

```json
{
  "Michelin": ["Мишелин"],
  "BF Goodrich": ["БФ гудрич", "BFGoodrich"],
  "Белшина": ["БШК", "Belshina"],
  "Sunrise": []
}
```

Пустой массив `[]` — у бренда нет альтернативных написаний; само каноническое
имя всё равно ищется в названии. Если бренда нет в файле, из названия он не
извлекается, а в колонке «Бренд» остаётся то, что дал поставщик.

Поиск без учёта регистра, по отдельным словам (в начале/конце названия или с
пробелами по краям); более длинные имена проверяются раньше коротких. Файл
должен оставаться валидным JSON, после правки — перезапуск разбора.

## Алиасы названий

Файл `parse_config/title_aliases.json` — синонимы названий. Подключается флагом
`aliases: true` у стратегии `title` и заменяет уже подготовленное название.

## Справочник номенклатуры

## Определение типа товара

Тип товара (`type_production`) определяется по названию и параметрам строки по
общепринятым в отрасли принципам. Колонка типа у поставщика при этом не источник
истины, а слабый ориентир для сверки.

Типы товара: `Легковая шина`, `Легкогрузовая шина`, `Грузовая шина`,
`Спецшина`, `Мотошина`, `Автокамера`, `Ободная лента`, `Уплотнительное кольцо`,
`Диск`. Сезон, шипы, бренд, цвет, `TL`/`TT`, `XL`, `RunFlat` — это атрибуты, а
не отдельные типы.

Порядок определения (первое совпадение выигрывает):

1. Сначала отсекаются нешинные позиции по ключевому слову: кольцо → камера →
   лента → диск. Это делается первым, потому что у камер и лент тоже бывают
   размеры, похожие на шинные.
2. Если это шина — ищется размер. Размер — самый устойчивый признак: он почти
   всегда присутствует и отделяет легковые от грузовых и спецшин.
3. Тип определяется независимо по названию и параметрам:
   - спецтехника (сельхоз, карьер, погрузчик, маркеры «клюшка», «волна»,
     «цельнолитая» и др.) → `Спецшина`;
   - мотоциклетный размер или маркеры → `Мотошина`;
   - большой диаметр, высокая слойность, «рулевая/ведущая/прицепная» ось →
     `Грузовая шина`;
   - пометки `C`/`LT`/`CP`, фургонные модели (`Van`, `Cargo`, …) →
     `Легкогрузовая шина`;
   - всё остальное → `Легковая шина`.

Правило про категорию поставщика: тип всегда вычисляется заново по названию и
параметрам. Колонка поставщика применяется только после этого — для
перекрёстной проверки. При расхождении приоритет у вычисленного типа,
расхождение фиксируется в логе. Если тип у поставщика не указан или не
распознан, позиция всё равно получает тип и не пропускается.

Работа независимого определения включается ключом `calculate_type: true` в слоте
`category` (например, у Мима и Пионера). Если он выключен, тип берётся из
стратегии слота (`fixed`, `tire_size_category`, `header_rows` и др.).

## Как добавить поставщика

1. Создайте `parse_config/vendors/<folder>.json` — имя файла равно имени папки
   в `file_prices` (готовый файл можно залить командой `load_config`).
2. Заполните уровень поставщика: `enabled`, `code`, `name`, `start_row`,
   `file_templates`, при необходимости `reader` и `behavior`.
3. Опишите хотя бы одну секцию с `columns` (индексы колонок Excel) и стратегиями
   `category` / `title`.
4. Задайте наценку в `pricing` (или политику `identity`, если цена уже
   отпускная).
5. Положите прайсы в `file_prices/<folder>/` и перезапустите разбор.

Если нужно поведение, которого нет среди готовых стратегий, — только оно требует
кода (новая именованная стратегия).

## Планы развития

- У номенклатуры поставщика нужен статус «активна/неактивна»: когда позиция
  исчезает из прайса или остаток становится нулевым, в базе её помечают
  неактивной; если позиция уже есть — обновляются цена и остатки.
- Переход на работу через базу данных и веб-интерфейс: загрузка общего прайса в
  базу, ручная правка номенклатуры и сведение дублей, наценка по правилам из
  настроек, формирование общего прайса и прайса для дрома из базы.
- Вынести наценку для Пионера в настройки.
- Наценка в разрезе принадлежности шины (грузовая/легковая/спецшина).
