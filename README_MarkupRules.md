# Настройки разбора прайсов поставщиков
Настройки хранятся в разделе `parse_config`:

- `vendors/<folder>.json` — по одному файлу на поставщика: колонки, стратегии разбора и наценка;
- `black_list` — глобальный чёрный список позиций;
- `manufacturer_aliases.json` — синонимы брендов;
- `title_aliases.json` — синонимы названий (подключается флагом `aliases` у стратегии `title`);
- `correct-nomenclature.xlsx` — справочник номенклатуры.

# Поставщик — один JSON-файл

Поведение поставщика полностью описывается файлом `parse_config/vendors/<folder>.json`.
Имя файла (без `.json`) совпадает с именем папки поставщика в `file_prices`:

```
parse_config/vendors/poshk.json   ↔   file_prices/poshk/price*.xls
parse_config/vendors/zapaska.json ↔   file_prices/zapaska/{disk.json,tire.json}
```

Новый поставщик добавляется без правки Python-кода. Код нужен только если
требуется принципиально новое поведение, которого нет среди готовых стратегий.

## Структура файла

```json
{
  "enabled": 1,
  "code": "1",
  "name": "Пошк",
  "start_row": 14,
  "file_templates": ["price*.xls", "price*.xlsx"],
  "reader": "xls",
  "category": { "strategy": "title_keywords", "map": { "шина": "Легковая шина" }, "default": "Разное" },
  "title": { "strategy": "normalize_size_chunks" },
  "pricing": { "policy": "map_on_opt", "rules": { "markup_rules": { "rule_70": { "min": 0, "max": 201, "percent": 0.7 } } } },
  "behavior": { "min_rest": 0 },
  "sections": [
    {
      "sheet_indexes": [0],
      "columns": { "0": "code", "1": "title", "2": "price_opt", "3": "rest_count" }
    }
  ]
}
```

### Уровень поставщика

| Ключ | Обяз. | Значение |
|---|---|---|
| `enabled` | да | `1` — разбор поставщика включён, `0` — выключен (попадает в `disabled_suppliers`) |
| `code` | да | внешний ИД каталога (например `1`, `22`); по умолчанию используется как `id` секций |
| `name` | да | название поставщика (по умолчанию для секций) |
| `start_row` | да | номер первой строки данных, 1-based (по умолчанию для секций) |
| `file_templates` | да* | glob-маски файлов прайсов в `file_prices/<folder>/` |
| `reader` | нет | `xls` (по умолчанию) или `json` |
| `columns` | нет | маппинг колонок по умолчанию для секций (см. ниже) |
| `pricing` | нет | наценки по умолчанию для секций (см. «Ценообразование») |
| `category`, `title` | нет | стратегии по умолчанию для секций |
| `behavior` | нет | общие переключатели разбора |
| `sections` | да | непустой список секций — по одной на лист/файл |

\* `file_templates` и `columns` обязательны хотя бы на одном уровне: либо у
поставщика, либо у каждой секции.

### Уровень секции

Секция — один лист (для `xls`) или один файл (для `json`). Отсутствующие ключи
берутся у поставщика.

| Ключ | Значение |
|---|---|
| `id` | ИД каталога; по умолчанию `code` поставщика |
| `name` | название; по умолчанию `name` поставщика |
| `start_row` | первая строка данных; по умолчанию у поставщика |
| `file_templates` | маски файлов; по умолчанию у поставщика |
| `sheet_info` | метка листа, добавляется к названию в отчёте (`«Мим (Вкладка #1)»`) |
| `sheet_indexes` | индексы листов xls, 0-based; пусто — все листы |
| `columns` | маппинг колонок; **заменяет** маппинг поставщика целиком |
| `category`, `title`, `pricing` | переопределяют одноимённые слоты поставщика |

Один поставщик может иметь несколько секций с разными `id` (например, Запаска →
`2` диски и `22` шины) или несколько секций с одним `id` (Мим — три вкладки).

## Колонки (`columns`)

`{"<источник>": "<поле позиции>"}`:

- при `reader: "xls"` ключ — индекс колонки (0-based) строкой: `"1": "title"`;
- при `reader: "json"` ключ — имя ключа исходной JSON-записи: `"cae": "code_art"`.

Значение — имя поля позиции. Поддерживаются, в частности:

```
code  code_art  code_man  title  manufacturer  brand  model  type_production
season  spike  width  height_percent  diameter  ext_diameter  tire_type
index_load  index_velocity  construction_type  axis  layering  intimacy
camera_type  inscription_on_the_side  run_flat  us_aff_designation
disk_thickness  slot_count  pcd1  pcd2  eet  central_diameter  fastener
disk_type  disk_type_1  color  main_color
price_opt  price_recommended  rest_count  reserve_count  delivery_period
condition  available
```

Поле, не указанное в `columns`, остаётся пустым.

## Стратегии

Стратегия задаётся именем в слоте; неизвестное имя — ошибка конфига с путём до ключа.

### `category` — тип товара строки

| Стратегия | Параметры | Что делает |
|---|---|---|
| `none` | — | не менять категорию из прайса (по умолчанию) |
| `fixed` | `value` | одна категория для всех строк секции |
| `title_keywords` | `map`, `default` | по вхождению ключевого слова в название (порядок ключей в `map` важен) |
| `field_map` | `field`, `map`, `default` | по значению поля через карту (регистр и пробелы нормализуются) |
| `column_canonical` | `unknown_skip` | канонизировать категорию из колонки; неизвестные → пусто |
| `header_rows` | `zero_rest_categories`, `map`, `default` | категория из строк-заголовков (состояние между строками): первый кусок канонизируется встроенной картой типов (`автошина`/`автошины` → `Автошина` и т.п.), `map` из конфига дополняет/переопределяет её, без совпадения — `default`, иначе сырой кусок; у перечисленных категорий остаток обнуляется |
| `tire_size_category` | — | категория по размеру и маркерам в названии: `Грузовая шина`, `Легкогрузовая шина`, `Легковая шина`, `Спецшина`, а также `Автокамера`, `Диск`, `Ободная лента` (Пошк) |

### `title` — подготовка названия

| Стратегия | Параметры | Что делает |
|---|---|---|
| `default` | — | оставить название как есть (по умолчанию) |
| `normalize_size_chunks` | — | нормализация названия (Пошк): `*`→`x`, склейка размера с `R`-диаметром |
| `tire_compose` | `variant` | собрать название шины: `mim_simple`, `mim_truck`, `four_tochki` |
| `disk_compose` | `variant` | собрать название диска: `four_tochki` |
| `fill_fields_from_title` | — | разобрать размер/модель из названия, само название не менять (Автоснабжение) |
| `manufacturer_from_category` | — | производитель из раздела-категории (Пионер) |

Флаг `aliases: true` дополнительно заменяет подготовленное название по
`title_aliases.json`.

### `pricing` — наценка

Политика (`policy`) и правила `rules`. См. раздел «Ценообразование».

### `behavior` — разбор строки

| Ключ | По умолчанию | Значение |
|---|---|---|
| `min_rest` | `4` | минимальный остаток; `0` — отсечка выключена |
| `rest` | `count` | `count` — остаток как есть; `minus_reserve` — `rest_count - reserve_count` |
| `skip_markup_without_opt` | `false` | не наценять строки без закупа |
| `zero_rest_without_category` | `false` | без категории остаток обнуляется |
| `collect_missing_recommended` | `false` | собирать строки без РРЦ в отчёт |
| `find_manufacturer_on_enrich` | `true` | искать производителя при обогащении |
| `pipeline` | `["title","min_rest","category","markup"]` | порядок шагов разбора строки |

`pipeline` принимает только шаги `title`, `min_rest`, `category`, `markup`.
Например, Пионер: `["category","min_rest","markup","title"]`.

## Как добавить поставщика

1. Создайте `parse_config/vendors/<folder>.json` — имя файла равно имени папки
   в `file_prices` (готовый файл можно залить командой `load_config`, см. README.md).
2. Заполните уровень поставщика: `enabled`, `code`, `name`, `start_row`,
   `file_templates`, при необходимости `reader` и `behavior`.
3. Опишите хотя бы одну секцию с `columns` (индексы колонок Excel) и стратегиями
   `category` / `title`.
4. Задайте наценку в `pricing` (или политику `identity`, если цена уже отпускная).
5. Положите прайсы в `file_prices/<folder>/` и перезапустите разбор.

# Активация поставщиков
Включение и выключение — ключ `enabled` в файле поставщика
`parse_config/vendors/<folder>.json`:
```json
{ "enabled": 1 }
```
`1` — разбор прайсов поставщика включён, `0` — выключен (в примере показан
только этот ключ; полный файл — выше).

# Черный список
Файл `black_list`. Действует на позиции прайсов всех поставщиков.
Каждая строка — одно правило, пустые строки пропускаются.

**Точное название.** Строка без символа `*` исключает позицию, если наименование совпадает целиком:
```
Основание обода колеса под камеру, , шт
Второе основание обода колеса под камеру, , шт
```

**Маска.** Если в строке есть `*`, это шаблон (без учёта регистра). `*` означает любую последовательность символов:
```
*некондиция*
*2 сорт*
восстановленная*
```
`*некондиция*` — фраза где угодно в названии, `восстановленная*` — название начинается с этой фразы.

# Алиасы производителей (брендов)
Файл `manufacturer_aliases.json`. Формат [JSON](https://ru.wikipedia.org/wiki/JSON).
Действует на позиции прайсов всех поставщиков.

Поставщики пишут один и тот же бренд по-разному: «Michelin» / «Мишелин», «BF Goodrich» / «BFGoodrich»,
«Белшина» / «БШК». Файл задаёт каноническое имя бренда и список таких вариантов.

Скрипт:
- ищет бренд в наименовании позиции и подставляет каноническое имя в название;
- записывает каноническое имя в колонку «Бренд» итогового прайса;
- если бренд уже есть в отдельной колонке прайса поставщика (а в названии его нет) — нормализует и это поле.

Одинаковое каноническое имя нужно, чтобы одна и та же позиция от разных поставщиков склеивалась в общий прайс.

## Формат
Ключ — как бренд должен выглядеть в результате. Значение — массив написаний, которые встречаются у поставщиков
(кириллица, слитно/через пробел, сокращения, старые названия, иногда модель вместо завода).
```
{
  "Michelin": ["Мишелин"],
  "BF Goodrich": ["БФ гудрич", "BFGoodrich"],
  "Белшина": ["БШК", "Belshina"],
  "НКШЗ": ["НК.ШЗ", "Кама", "Kama", "Кама-505"],
  "Sunrise": []
}
```
Пустой массив `[]` — у бренда нет альтернативных написаний. Само каноническое имя всё равно ищется в названии
(и регистр в названии приводится к ключу: `RockBuster` → `Rockbuster`).

Если бренда нет в файле, из названия он не будет извлечён. В колонке «Бренд» останется то, что было в прайсе
поставщика (если такая колонка есть).

## Как добавить бренд или написание
1. Откройте `parse_config/manufacturer_aliases.json`.
2. Новый бренд — новая пара ключ/массив. Уже известный бренд — допишите строку в его массив.
3. Файл должен остаться валидным JSON: запятые между элементами, без комментариев, без запятой после последнего элемента.
4. Перезапустите разбор прайсов (`run.bat`).

Поиск без учёта регистра: «мишелин» и «Мишелин» — одно и то же.
Совпадение — отдельным словом: в начале или в конце названия, либо с пробелами по краям.
Более длинные имена проверяются раньше коротких, поэтому «Кама-505» сработает раньше «Кама».

Дублировать ключ в массиве не нужно: `"Белшина": ["Белшина", "БШК"]` достаточно записать как `"Белшина": ["БШК"]`.

# Ценообразование
Наценка поставщика задаётся слотом `pricing` в его файле
`parse_config/vendors/<folder>.json`. Слот состоит из политики `policy` и правил
`rules`; у секции может быть свой `pricing`, который переопределяет поставщика.

Политики (`policy`):

- `base` — наценка по карте `rules` (по умолчанию);
- `identity` — без наценки (цена из прайса уже отпускная, например Автоснабжение);
- `map_on_opt` — наценка по карте `%` от опта;
- `recommended_or_map` — РРЦ, если она есть, иначе карта `%` (Форточки);
- `percent_by_threshold` — фиксированный процент в зависимости от закупа:
  `rules.threshold`, `rules.low`, `rules.high` (наценка Мим, грузовая вкладка).

## Правила `rules`

Правило содержит диапазон оптовых цен (`min`/`max`), в рамках которого применяется
наценка; процент наценки — поле `percent`. Для новых файлов канон — ключ `percent`,
синоним `percent_markup` тоже принимается. Если указаны оба — берётся `percent_markup`.
```
"rules": {
  "markup_rules": {
    "rule_70": { "min": 0, "max": 201, "percent": 0.7 },
    "rule_50": { "min": 200, "max": 301, "percent": 0.5 },
    "rule_40": { "min": 300, "max": 501, "percent": 0.4 }
  },
  "min_recommended_percent_markup": 0.14,
  "max_recommended_percent_markup": 0.27,
  "absolute_markup_rules": {
    "min_absolute_markup": 200,
    "markup_percent": 1.5
  }
}
```
Примечание №1: `rule_70` / `rule_50` / `rule_40` — название правила, в алгоритме
наценки не участвует. Должно быть уникальным в рамках `markup_rules`.
Примечание №2: если для оптовой цены нет подходящего ценового диапазона,
наценка идёт по минимальному проценту. Для примера выше — 0,4 %.

Необязательные поля (если ключа нет — как у Пошка):

`min_recommended_percent_markup` / `max_recommended_percent_markup` — минимально
и максимально допустимая наценка по РРЦ (актуально, если у поставщика есть РРЦ).

`replace_small_recommended` — подменять ли РРЦ картой `%`, когда наценка по РРЦ
меньше `min_recommended_percent_markup`:
- `false` (по умолчанию) — если РРЦ есть, её не трогают (дальше только абсолютный пол);
- `true` — при малой марже вместо РРЦ считается `закуп * (1 + percent)`. На самом
  пороге РРЦ оставляют (как у Мим: строго меньше минимума).

`absolute_markup_rules.mode` — что делать, если рублёвая маржа меньше `min_absolute_markup`:
- `multiplier` (по умолчанию) — цена = `закуп * markup_percent`;
- `delta` — цена = `закуп + min_absolute_markup` (поле `markup_percent` не используется).

## Примеры поставщиков

- **Пошк** — `policy: map_on_opt`, карта от 70 % на дешёвые позиции, `min_rest: 0`,
  категория `tire_size_category` (грузовые, легкогрузовые и легковые по размеру).
- **Мим** — три секции; легковые (1) и диски (3) — `policy: base`, грузовая
  вкладка 2 — `percent_by_threshold` (`threshold: 13000`, `low: 0.07`, `high: 0.05`).
- **Форточки** — `policy: recommended_or_map`, title `tire_compose(four_tochki)` и
  `disk_compose(four_tochki)`.
- **Запаска (диски и шины)** — `reader: json`, `policy: base` с порогом РРЦ 8 %,
  `replace_small_recommended: true` и абсолютным полом `mode: delta`, `+150` ₽.
- **Автоснабжение** (`autosnab54_ru`) — `policy: identity`: цена в прайсе уже отпускная.
- **STK** — все настройки (включая наценку) в своём файле; отдельного
  `stk_markup_rules.json` больше нет.
