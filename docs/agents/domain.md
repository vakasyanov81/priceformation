# Domain docs

## Перед исследованием кодовой базы

Прочитать корневой `CONTEXT.md` и ADR из `docs/adr/`,
относящиеся к рассматриваемой области.

Если документов ещё нет, продолжать работу без уведомлений
и предложений создать их заранее. Навык domain-modeling создаёт
их по мере согласования терминов и решений.

## Структура

Single-context:

- `CONTEXT.md` — доменные термины проекта.
- `docs/adr/` — архитектурные решения.

## Терминология

Использовать термины из CONTEXT.md в задачах, предложениях,
гипотезах и названиях тестов.

Если нужного понятия нет, проверить, соответствует ли оно языку проекта.
Реальный пробел отметить для domain-modeling.

## Конфликты решений

Если предложение противоречит существующему ADR, явно указать
номер ADR и причину пересмотра.
