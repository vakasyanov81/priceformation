# Task-19: Убрать `# flake8: noqa` из `parsers/base_parser/base_parser.py`

**Статус: выполнено.** `BaseParser` разложен на цепочку слоёв-миксинов в `parsers/base_parser/`: `parser_core` → `parser_files` → `parser_title` → `parser_rows` → `parser_category` → `parser_markup` → `parser_pipeline` → `BaseParser` (парсинг, `process`, `after_process`, `enrich`, `filter_keep`). Каждый класс ≤ 7 методов, публичный API и MRO для вендорных подклассов не изменились. `_run_pipeline` разбит на `_run_step`. Остаточный долг: слои делят состояние через `self`, полноценная композиция потребует отдельной задачи.

## Проблема

В первой строке `src/parsers/base_parser/base_parser.py` стоит файловая директива `# flake8: noqa: WPS201`. Без неё `uv run flake8 .` падает на трёх нарушениях:

- `WPS201` — 24 импорта при `max-imports = 18` (`setup.cfg`);
- `WPS214` — в `BaseParser` 52 метода при лимите 7;
- `WPS231` — когнитивная сложность `_run_pipeline` 15 при лимите 12.

Директива названа одним кодом, но скрывает все WPS-нарушения файла. Новые нарушения в нём остаются незамеченными.

Корень: `BaseParser` совмещает несколько ролей — чтение файла, обход строк, конвейер стратегий над `RowItem`, статистику и логирование. Импорты и число методов растут вместе с ними. Одним выносом импортов проблему не решить: останется `WPS214`.

## Решение

Разложить `BaseParser` по ролям так, чтобы лимиты выполнялись без подавлений. Состав модулей определить на этапе 1.

1. Составить карту 52 методов по ролям (чтение, обход строк, конвейер стратегий, статистика, логирование, публичный API для наследников).
2. Выделить роли в композиционные объекты в `parsers/base_parser/` (по образцу `StrategyHooks`, `RowProcessor`); `BaseParser` оставить фасадом с публичным API, на который опираются конфиг-драйвен парсеры и тесты.
3. Разбить `_run_pipeline` на шаги, чтобы сложность стала ≤ 12.
4. Снять директиву. `per-file-ignores` в `setup.cfg` и `# noqa` не добавлять: это то же подавление в другом месте, для `src/` оно запрещено.

Ограничение: слои из `lint-imports` не нарушать, публичные сигнатуры `BaseParser` и поведение парсеров не менять (паритет — `integration_tests/test_parity_vendor_config.py`).

## План миграции

1. Карта методов по ролям, согласование границ.
2. Вынос ролей по одной, каждый шаг — полный набор проверок.
3. Разбиение `_run_pipeline`.
4. Удаление директивы.
5. Прямые тесты на новые объекты, если они покрыты только косвенно (порог 95 %).
