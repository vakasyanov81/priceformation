# task-17: единое название номенклатуры у всех поставщиков

Статус: 📝 задача поставлена (2026-10-20), решения Р1–Р7 приняты, к работе не приступали.

Цель: один и тот же товар у одного и у разных поставщиков получает **в точности одинаковое** название в `price_*.xlsx`, `price_drom_*.xlsx`, `doubles_*.xlsx`. За основу берутся названия, которые мы собираем сами (стратегии `tire_compose`, `poshk_stk_tire_compose`, `disk_compose`), а не текст из прайса поставщика.

## Основание: анализ `file_prices/result/*_2026-10-20.xlsx`

Файл дублей: 3467 групп одного товара (`Группа по параметрам`), из них в **1564 группах (45 %) названия различаются**.

| Грузовая шина | 75 | 5 | — |
| Легкогрузовая шина (в т. ч. `*`) | 68 | — | — |

Значит, собирать название из полей можно у всех, а не только у «наших» поставщиков.

## Корень проблемы

1. **Нет одного шаблона.** Название — выход стратегии слота `title`, и у каждой стратегии свой порядок и свой набор токенов. Для Запаски, Пионера и Автоснабжения название — исходный текст поставщика, хотя поля из него уже разобраны (`params_from_title`).
2. **Кириллические буквы-двойники в технических токенах.** Поставщики набирают `TТ` (вторая `Т` кириллическая), `R16С`, `86Н`, `ЕТ35`. Визуально строки одинаковы, а для сравнения и для поиска на Дроме — разные. Сейчас двойники сводятся только в ключе группы и при определении камерности (`replace_homoglyphs` в `clear_model`, `define_intimacy`, task-16), а поля и название остаются с кириллицей.
3. **Нет приведения внутри группы.** Даже при общем шаблоне поставщики по-разному пишут модель (`iceGuard Studless G075` / `Ice Guard G075`), регистр и набор признаков (`XL` есть только у Запаски). Ключ группы это уже учитывает (`clear_model`, `merge_models`, task-16), а название — нет.

Слой: `parsers` (стратегии `title`, `nomenclature_title.py`, `CommonPriceGrouper`). Шаблоны writer (`for_inner`/`for_drom`/`for_full`) **не трогаем** — они выводят готовое название.

## Решение

Три ступени: исправление букв-двойников в полях (ступень 0), канонический сборщик (одинаковые поля → одинаковое название, ступень 1) и одно название на группу (ступень 2).

### Ступень 0. Кириллические буквы-двойники

Смешанные латиница и кириллица в одном токене встречаются у всех поставщиков (прайс 2026-10-20): Форточки диски 32 строки, Запаска диски 22, Пионер 18, Мим 10, Пошк 5, Запаска шины 5, Форточки шины 3. Ещё есть токены целиком из кириллических двойников там, где по смыслу нужна латиница (`ЕТ35`, `86Н`, `ТТ`).

Двойники: заглавные `А В Е К М Н О Р С Т Х` ↔ `A B E K M H O P C T X`, строчные `а е о р с х` ↔ `a e o p c x`. Таблица уже есть в `normalize.py` (`_CYRILLIC_HOMOGLYPHS`), её нужно переиспользовать, а не заводить вторую. Дополнить: `у` ↔ `y`; проверить строчные `в н т к м` — в строчном виде они на латиницу не похожи, поэтому в смешанной части их не переводить, а отправлять в лог (правило 3).

**Где чинить.** Неверные данные появляются при разборе колонок и названия поставщика, поэтому чинить нужно там (`fill_tire_fields`, разбор дисков, стратегии `category`/`title`), а не на выходе сборщика. Тогда латиница попадёт и в поля, и в ключ группы, и в название. Правило — чистая функция рядом с `replace_homoglyphs`.

**Правило по классу токена:**

1. **Технические токены — всегда латиница.** Размер (`R16С` → `R16C`, `1200х500-508` → `1200x500-508`), нагрузка+скорость (`86Н` → `86H`), слойность `PR`, камерность (`TТ`/`ТT`/`ТТ` → `TT`), `XL`, `ET` диска (`ЕТ35` → `ET35`), суффикс `C`/`LT`.
2. **Слова модели и бренда — по преобладающему алфавиту.** Токен делится по разделителям (`-`, `/`, `+`, `(`, `)`, `=`); в части, где смешаны алфавиты, двойники приводятся к алфавиту, которого в ней больше. Части в одном алфавите не меняются.
3. **Не исправлять, а сообщить.** Если в части смешаны алфавиты, а меньшинство — не двойники (`Каzантип`: `z` не имеет кириллической пары), или токен целиком кириллический там, где у других поставщиков латиница (`Н168` у Rockbuster, `H168` у остальных): писать в лог разбора (file-only) и считать в статистике. Внутри группы такое написание исправит ступень 2.

Каждое исправление считается в статистике разбора по поставщику (`ParseStatistic`): видно, у кого и сколько опечаток.

**Примеры (готовые кейсы для тестов):**

| Было | Стало | Почему |
|---|---|---|
| `TТ`, `ТT`, `ТТ` | `TT` | камерность |
| `215/75R16С`, `195R15С` | `215/75R16C`, `195R15C` | суффикс размера |
| `1200х500-508` | `1200x500-508` | размер камеры |
| `86Н`, `102Н` | `86H`, `102H` | индекс скорости |
| `ЕТ35` | `ET35` | вылет диска |
| `150/136A2/А6` | `150/136A2/A6` | нагрузка спецшины |
| `Asimmetriсo`, `Аvео` | `Asimmetrico`, `Aveo` | в слове больше латиницы |
| `VС-1`, `СR-17`, `H108А`, `H108С`, `Е3/L3`, `B-Р` | `VC-1`, `CR-17`, `H108A`, `H108C`, `E3/L3`, `B-P` | смешанная часть, больше латиницы |
| `НК-241`, `Кама-310`, `О-79`, `В-105А`, `СВК`, `КС1053` | без изменений | части целиком кириллические — это русские модели и коды |
| `Samara-оригинал`, `Сахара-Patriot`, `(Jac/Москвич`, `SUNTOP+монтажный`, `d=6.6мм`, `16мм` | без изменений | каждая часть в одном алфавите |
| `Каzантип`, `Н168` | без изменений, в лог | исправить по правилу нельзя |

`В60.1` (диаметр ступицы Запаски с кириллической `В` вместо `D`) двойником не является. Он исчезнет сам: в шаблоне диска `DIA` собирается из поля `central_diameter` без буквы.


### Ступень 1. Канонический сборщик названия

Одна функция сборки на тип товара (`src/parsers/nomenclature_title.py`, чистая, без IO), которую вызывают все стратегии слота `title`.

**Шина** — «порядок Пионера», он уже выбран для Пошка/STK (`tasks/merge-poshk-stk-tire-compose.md`):

```
<размер> <бренд> <модель> <нагрузка+скорость> [XL] [<N>PR] [TT|TTF|TL] [RunFlat] [ось]
205/55R16 Triangle ReliaX Touring TE307 91V
10.00R20 Кама И-281 У-4 146/143J 16PR TT
315/80R22.5 Cordiant Professional FR-2 156/150L Рулевая
17.5-25 Rockbuster H168 G2/L2 28PR TT
```

Правила токенов:

- **Размер**: `x` строчная, без пробелов, суффикс `C`/`LT` латиницей, без `.00` после дробной ширины (`8.25R20`), `31x10.5R15LT`; легкогрузовая без суффикса получает `C`.
- **Бренд**: каноническое имя из `manufacturer_aliases.json` как есть (без `lower().capitalize()`), без владельца в скобках (`Ikon`, не `Ikon (Nokian Tyres)`).
- **Модель**: без повторённого бренда в начале (`КАМА-NF 701` → `NF 701`, `Ikon Character` → `Character`); регистр — см. ступень 2.
- **Нагрузка+скорость** одним токеном (`86T`, `154/150L`, `160A8`).
- **Слойность** всегда `<N>PR`.
- **Камерность** латиницей (`TT`/`TTF`/`TL`).
- **Ось/назначение** из словаря: `Рулевая` / `Ведущая` / `Прицепная` / `Универсальная` / `Карьерная` (`рул.ось`, `вед.`, `руль/ прицеп` → канон).
- **Не входят в название** (уже есть в отдельных колонках или это шум): `M+S`, `3PMSF`, `шип`/`шипы`/`Stud`-маркер (колонки `Сезон`/`Шип`), завод `НкШЗ`/`ОШЗ`/`ЯШЗ`, год `г.в.`, `б/к`, `спецшина`/`клюшка`/`(цельнолитая)` (Р4).

**Диск** — шаблон Форточек:

```
<ширина>x<диаметр> <отверстия>x<PCD> ET<вылет> <DIA> <Цвет> <бренд> <модель> [(код)] [хвосты]
6.0x15 4x98 ET35 58.6 Графит СКАД Порту (КЛ321)
```

`DIA` без `D`, цвет с заглавной буквы, хвост (`disk_name_suffix`) — один раз.

**Автокамера / ободная лента**: `Камера <размер> [бренд] [модель]`, `Ободная лента <размер>` (`130-10 об/лента` → `Ободная лента 130-10`).

Стратегии переводятся на канонический сборщик:

| Стратегия | Поставщики | Что меняется |
|---|---|---|
| `tire_compose` (`four_tochki`, `mim_simple`, `mim_truck`) | Форточки, Мим | порядок, `PR`, без `M+S`/`3PMSF`/`TL` у легковых |
| `poshk_stk_tire_compose` | Пошк, STK | `TireTitleParts.compose` заполняет поля, название собирает общий сборщик; ось — из словаря |
| `normalize_title` | Запаска | новая стратегия или флаг `compose: true` — название из уже разобранных полей |
| `manufacturer_from_category`, `fill_fields_from_title` | Пионер, Автоснабжение | то же |
| `disk_compose` | Форточки диски, Запаска диски | общий шаблон диска |

Если для сборки не хватает обязательных полей (размер, бренд или модель), остаётся нормализованный исходный текст, а позиция считается в статистике разбора («название не собрано») — без молчаливого отката.

### Ступень 2. Одно название на группу

После `CommonPriceGrouper._assign_groups` (там уже есть объединённая модель из `keys_with_merged_models`) всем позициям группы назначается одно название:

- **модель** — объединённая модель ключа (самая полная по `merge_models`: `Ice Guard G075` + `iceGuard Studless G075` → одна); её написание (регистр, пробелы) — у поставщика-эталона;
- **остальные токены** — от поставщика-эталона; эталон — первый по приоритету поставщик группы (порядок — Р6);
- название собирает тот же сборщик ступени 1 из полей эталона, а не копирует строку.

Порядок эталонов задаётся конфигом, а не кодом (новый поставщик = JSON): например, `title.reference_priority` в `vendors/*.json`.

`XL` — исключение: пишется, если есть хотя бы у одной позиции группы (Р3).

Группы, которые сознательно режутся (цвет диска, `TL`/`TT`, `ET-10`/`ET10`, `WP52`/`WP52+` — см. task-16 «Не дубли»), остаются разными группами и названия у них разные — это верно.

### Попутные баги (отдельными коммитами, по правилу «один фикс — одна причина»)

1. Хвост диска Форточек повторяется (`(Logan) (Logan) (Logan)`, 266 строк): название собирается несколько раз (как с суффиксом `C` в `_fill_size_suffix`), и хвост дописывается к уже собранному. Найти, где `disk_name_suffix` получает собранное название вместо исходного.
2. `8.25.00R20` у Форточек (`_resolve_width_postfix`: `.00` дописывается к дробной ширине).
3. `brand_label` (`lower().capitalize()`) портит регистр бренда.
4. Бренд, повторённый в модели (Мим `КАМА-NF`, `Ikon Ikon`; Форточки `Кама Кама-310`, `Forza Forza`).

## Решения (2026-10-20, приняты пользователем)

| # | Вопрос | Решение |
|---|---|---|
| Р1 | Канонический порядок шины | «Порядок Пионера» (`размер бренд модель LISI PR камера ось`) — уже используется у Пошка/STK; Форточки и Мим переходят на него |
| Р2 | `TL` у легковых | Не писать (у Запаски и Мима его нет; 99 % легковых бескамерные). У грузовых/спец — писать всегда: камерность различает товар |
| Р3 | `XL` | Писать, если есть хотя бы у одной позиции группы (это свойство шины, а не шум) |
| Р4 | `M+S`, `3PMSF`, `шип`, год, завод | Не писать: сезон и шип — в колонках, год — уценка/остаток, завод — тот же бренд |
| Р5 | Ось/назначение у грузовых | Писать из канонического словаря; в группе — от эталона |
| Р6 | Поставщик-эталон | Форточки → Автоснабжение → Запаска → Мим → STK → Пионер → Пошк |
| Р7 | Переименование на Дроме | Не мешает: база Дрома перезаливается полностью, объявления к названию не привязаны — проверка не нужна |

| 3 | Сборка из полей у Запаски, Пионера, Автоснабжения | счётчик «название не собрано» ≈ 0 на боевых прайсах |
| 4 | Канонический сборщик диска (Форточки + Запаска) | сверка групп дисков |
| 5 | Камеры, ободные ленты | сверка групп |
| 6 | Одно название на группу (ступень 2) | интеграционный тест: в каждой группе ровно одно название |
| 7 | Документация (`README.md`, `AGENTS.md`) | — |

## Критерии приёмки

- В `doubles_*.xlsx` число групп, где названий больше одного, — **0** (сейчас 1564 из 3467).
- Одинаковые поля дают одинаковое название у любого поставщика (тест сборщика: одна и та же шина из полей Форточек, Мима, Запаски, Пошка → одна строка).
- Внутри одного поставщика повторяющиеся позиции (разные склады) имеют одно название.
- Нет токенов со смешанной латиницей и кириллицей, кроме допустимых составных (`Samara-оригинал`, `d=6.6мм`) и случаев из лога ступени 0. В технических токенах (размер, индексы, `PR`, камерность, `XL`, `ET`) — только латиница.
- Нет названий с повторённым брендом, повторённым хвостом, `X`/`*`/кириллицей/пробелом в размере, `.00` после дробной ширины.
- Интеграционный тест на эталонных прайсах (`integration_tests/file_prices_for_test/`): для каждой группы `len({title}) == 1`.
- Полный набор проверок из `AGENTS.md` — exit 0.

## Как повторить анализ

Сравнить названия внутри групп файла дублей: строки с одинаковым `Группа по параметрам` и разной `Номенклатура`; классифицировать токены по шаблону (`SIZE`/`LISI`/`PR`/`CAM`/`MS`/слова) по поставщику на `price_*.xlsx`. Заполненность полей — `ParseOrchestrator().parse_all()` после `init_cfg()` и `configure_services()`, без записи результата.
