# Task-20: Убрать `# flake8: noqa: WPS202` из двух модулей стратегий

## Проблема

Первой строкой стоит файловая директива `# flake8: noqa: WPS202` в:

- `src/parsers/strategies/_four_tochki_tire_helper.py` (246 строк);
- `src/parsers/strategies/_tire_title_parser.py` (513 строк).

Название директивы — один код, но она глушит всё WPS в файле. Без неё `uv run flake8 .` показывает:

| Файл | Нарушения |
| --- | --- |
| `_four_tochki_tire_helper.py` | `WPS202` (15 членов модуля > 7), `WPS237` (сложная f-строка, стр. 117), `WPS110` (имя `value`, стр. 127) |
| `_tire_title_parser.py` | `WPS202` (28 > 7), `WPS210` ×2 (7 локальных > 5, стр. 192 и 296), `WPS221` ×8 (Jones-сложность 16–19 > 14), `WPS237` ×2 (стр. 168, 262) |

Корень: оба модуля копят в одном файле несколько ролей. `_tire_title_parser.py` совмещает разбор названия шины (Пошк, STK, Пионер) и его сборку, с отдельными ветками по поставщикам; `_four_tochki_tire_helper.py` — сборщики названий листа 1. Число членов модуля — следствие, сложные выражения и локальные переменные — отдельная проблема в функциях.

## Решение

Для каждого файла отдельным шагом (один шаг — одна причина):

1. Разбить модуль по ролям на пакет-соседей в `parsers/strategies/` (например, токены и регулярки / разбор в `TireTitleParts` / сборка названия); границы определить по карте функций до правки.
2. Упростить функции с `WPS210`, `WPS221`, `WPS237`: вынести промежуточные значения в именованные функции или frozen-VO, а не растягивать строки.
3. Переименовать `value` в `_four_tochki_tire_helper.py`.
4. Снять директиву. `per-file-ignores` и `# noqa` не добавлять.

Ограничение: формат названий не меняется (`tests/test_parsers/`, `integration_tests/test_parity_vendor_config.py`); публичные имена, которые импортируют `nomenclature_title.py` и стратегии слота `title`, сохранить или обновить импорты за один проход.

## План миграции

1. Карта функций и констант по ролям для обоих файлов.
2. Файл `_four_tochki_tire_helper.py` (меньший): разбиение, правка `WPS237`/`WPS110`, снятие директивы, полный набор проверок.
3. Файл `_tire_title_parser.py`: разбиение, затем по одному классу нарушений (`WPS210`, `WPS221`, `WPS237`), снятие директивы, полный набор проверок.
4. Прямые тесты на новые модули, если покрыты только косвенно (порог 95 %).
